# Демо на защите: тестовые фото

Постановка требует «демонстрацию обработки тестового набора изображений» и «выходной отчёт/таблицу с перечнем объектов». Сценарий ниже даёт и то и другое. Команды ML из `ml/README.md`, код ML не меняем.

## До защиты (за 15 минут)

1. Ключ и сеть: `cd ml && .venv/bin/python smoke_decision.py <любое фото>`.
2. Стенд: `docker compose up -d`, API на `:8080`, интерфейс открыт под ролью «Диспетчер».
3. Дека: `design2/deck/index.html?track=3` (или `deck-poputno.html`) во второй вкладке, `F` полный экран.
4. Запасной вариант: `deck/deck-3.pdf` на рабочем столе и отчёт `ml/runs/dss-final2/report.md`.

## Во время защиты: сценарий на ~3 минуты (из документа команды «пайплайн решения»)

Организаторы требуют прогнать на защите весь датасет, поэтому прогоняем его вживую.

| # | Что делаем | Что видит жюри |
|---|---|---|
| 1 | **Одно фото.** Экран «Проверить фото», перетащить снимок упавшего ТКШ (ТКШ-36955095) | Через ≈2 с красная карточка «Критично · Нарушение крепления · Срочный выезд бригады» |
| 2 | **Весь датасет.** Загрузить zip организаторов как есть | Прогресс «47 из 62», через ≈20 с готово, качество считается против их же разметки |
| 3 | **Очередь.** Показать, что человеку достались только спорные и опасные, критичные сверху. Подтвердить один кадр клавишей Y | Статус объекта меняется сразу |
| 4 | **Качество.** Страница «Качество» | 41 из 41 дефекта дошли до человека; таблица порога: сколько снимаем с людей и с какого места теряем дефекты |
| 5 | **Таблица для жюри.** Скачать XLSX | Повреждённые сверху, цвет по выводу, рекомендация, колонка «Совпало с разметкой» |
| 6 | **Под капотом**, если спросят | Swagger `/api/docs` и Kafka UI: история каждого объекта журналом событий |

Загрузка zip с прогрессом и кнопка «Скачать таблицу» сейчас доступны через API и Swagger, в интерфейс их добавляет фронтендер. Проверить перед защитой, где они.

Если дали отдельные тестовые фото, их можно прогнать и из консоли:

```bash
cd ml
.venv/bin/python worker.py <папка тестовых фото> --run-id test --kafka ''          # без системы: только predictions.jsonl
.venv/bin/python worker.py <папка тестовых фото> --run-id test                      # в систему через Kafka
# если у тестовых фото есть разметка:
.venv/bin/python evaluate.py runs/test --labels <таблица> --label-col class --kind-col kind
```

Обновить цифры деки на тестовом прогоне (только если есть разметка, иначе оставляем `dss-final2`):

```bash
cd design2/deck && python3 tools/build-data.py --run test && python3 tools/inline-numbers.py
```

Если ID сквозного примера нет в тестовом прогоне, поменять `EXAMPLE` и `REGISTRY` в начале `tools/build-data.py`.

## План Б

| Что сломалось | Что делаем |
|---|---|
| Нет сети или OpenRouter | Ответы модели на все фото датасета уже в кэше, повторный прогон идёт без сети. Новые фото: говорим «нет сети», показываем слайды «Решение», «Результаты» и «Сайт» на `dss-final2` |
| Стенд не поднялся | Показываем деку: слайды «Решение» и «Результаты» собраны из реальных ответов модели, «Сайт» из скриншотов |
| Не открывается браузер | `deck-3.pdf` |
