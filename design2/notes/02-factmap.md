# 02 — Разбор эталона: Factmap «Дизайн-система»

Источник: `design2/factmap-design-system.html` (670 КБ, один файл: 6 woff2-шрифтов base64, ~1800 строк CSS, ~3100 строк JS, ~190 КБ разметки).
Скриншоты: `design2/notes/shots/factmap-{light|dark}-{section}.png`, 1440×3600, по 18 секций в каждой теме.
Снимались с `--force-prefers-reduced-motion`, поэтому на снимке «Длительности» везде `1ms`: это сработал режим «меньше движения», а не ошибка.
Хэш-ссылка на секцию в headless давала пустой кадр из-за `content-visibility: auto`. Поэтому для съёмки подключался скрипт, который прячет остальные секции.

Мета: `<title>Factmap | Дизайн-система</title>`, `lang="ru"`, `theme-color` light `#f4f5f1` / dark `#12140f`, favicon сделан из того же SVG-знака (data-URI).
В шапке подпись версии `v1.0, 25.10.2026`. В подвале навигации указан источник правды: `Токены: tokens.css`, `Сборка: node build.mjs`.

### 2.5 Глубина (тени)
```
--shadow-ring:    inset 0 0 0 1px var(--border-default)                    — карточки на странице: только линия
--shadow-raised:  0 1px 2px var(--shadow-color)                            — ползунок switch
--shadow-float:   0 0 0 1px var(--border-subtle), 0 4px 14px var(--shadow-color)       — поиск, контролы карты, легенда
--shadow-overlay: 0 0 0 1px var(--border-subtle), 0 16px 48px var(--shadow-color-strong) — меню, диалог, тост
--shadow-pin:     0 0 0 1px var(--border-default), 0 3px 10px var(--shadow-color)      — метки на карте
```
Принцип: поверхности плоские, между ними линия 1 px через inset box-shadow (а не border, чтобы не менять размер). Тень получает только то, что лежит над картой или над страницей.

### 2.6 Движение
```
--ease-out      cubic-bezier(0.23, 1, 0.32, 1)    вход, отклик, hover (по умолчанию)
--ease-in-out   cubic-bezier(0.77, 0, 0.175, 1)   перемещение, маршрут, смена темы
--ease-drawer   cubic-bezier(0.32, 0.72, 0, 1)    нижний лист, боковая панель
--ease-fold     cubic-bezier(0.65, 0, 0.35, 1)    складывание знака / загрузчик
--dur-instant 80 | press 140 | fast 160 | fast-exit 110 | base 200 | exit 140 | panel 260 | panel-exit 200
--dur-slow 320 | reveal 560 (смена темы) | fold 720 | draw 900 (маршрут) | spin 800 | breathe 1600
--stagger 40ms; --stagger-roll 18ms
--press-scale 0.97; --press-scale-surface 0.99; --enter-scale 0.95
--shift-rise 6px; --shift-anchor 4px; --shift-roll 0.5em; --shift-toast 24px; --blur-soft 2px
--delay-skeleton 200ms; --hold-skeleton 300ms; --delay-spinner 400ms; --delay-tooltip 500ms
--toast-life 5000ms; --toast-life-error 10000ms
--transition-control: bg/color/border-color var(--dur-fast) ease-out, scale var(--dur-press) ease-out
```
При `prefers-reduced-motion: reduce` все `--dur-*` становятся `1ms`, stagger 0, scale 1, сдвиги и blur 0. Сами компоненты не меняются, переопределяются только токены.
Keyframes: `kf-fade-in/out`, `scale-in/out`, `rise-in`, `anchor-in/out` (translateY −4 и scale .95 от якоря), `swap-in/out` (сдвиг и blur 2px), `roll-in/out` (смена цифр), `toast-in/out`, `sheet-in/out`, `drawer-in/out`, `shimmer` (opacity 1→.45→1), `spin`, `draw` (stroke-dashoffset), `pin-drop`, `fact-ping` (scale 1→2.4, fade), `viewshed` (clip-path circle 0→150%), `fold-left/mid/right` (зацикленный загрузчик), `unfold-side/mid` (однократное раскрытие знака).
Правила: ответ на клик короче 300 мс, выход короче входа, пружин нет, ширину и высоту не анимируем. Выразительное движение только у редких событий.

Всё на `--dur-fold 720ms --ease-fold`, `transform-box: fill-box`. Смысл: «факт появляется, когда карта готова». Это же движение в цикле (`kf-fold-*`, `--dur-breathe`) служит единственным фирменным загрузчиком. Показывается один раз за сессию вкладки (sessionStorage).

## 6. Голос и тексты

- Позиция: «внимательный местный житель, который проверил за вас: конкретно, спокойно, с цифрами и источником».
- Мы точные, тёплые, спокойные. Не рекламные, не болтливые, не тревожные. Каждая пара показана живым примером (хороший пример плюс перевод EN, плохой зачёркнут).
- Главный принцип: неизвестное называется неизвестным и не путается с «нет» («Нет данных о шторах. Спросили отельера, ответ появится здесь.»).
- Ответ ассистента: итог одной фразой («Нашёл 24 отеля.»), от первого лица, простые глаголы (нашёл, исправил, досчитываю). Без рассуждений модели, процентов без источника, эмодзи, «Отличный выбор».
- Кнопки строятся как глагол и объект («Показать на карте», «Вернуть эту выдачу», «Убрать «бары рядом»»).
- Ошибка = Что, Почему, Что сделать, Кнопка. Пустое состояние = что не нашли и какое **одно** условие убрать. Текст сервера не показываем, только текст из словаря по коду.
- Пунктуация: «ёлочки» в RU, "…" в EN; буква ё; en dash только в диапазонах; заглавная только в начале фразы. Запрещено длинное тире, точка-разделитель «·», стрелки и галочки символами, «Загрузка…» вместо скелетона, прочерк вместо «нет данных», «!», капслок, «идеальный» и «лучший».
- Словарь: термин, определение, «Не говорим: ~~синонимы~~» (Факт ≠ свойство/фича; Уверенность ≠ скор/рейтинг; Срок годности ≠ TTL; Пожелание ≠ фильтр/тег…).
- Заголовок вкладки: на главной «Продукт | слоган», на остальных «Страница | Продукт». Вертикальная черта разрешена только здесь.
- Форматы через `Intl` (ru / en): `24 октября 2026 г.`, `24.10.2026`, `420 м`, `6 мин`, `0,72`, `72 %`, `12 400 ₽`, plural rules.

## 7. Почему это ощущается качественным — приёмы для переноса

1. **Документ сам сделан на своей системе.** Шапка, навигация, кнопки и таблицы брендбука собраны из тех же токенов и компонентов, что описывает документ. Нет отдельной «презентационной» стилистики.
2. **Каждый блок открывается правилом, а не описанием.** Одна-две фразы с конкретными числами («Сетка 64. Полосы 17, 14 и 17 с зазором 3…»). Ни одного абзаца-воды.
3. **Демо живые и проверяемые.** Контраст считается в браузере для текущей темы, motion-карточки проигрываются, свотчи копируются, чат отвечает, тумблер grayscale доказывает правило «не только цветом».
4. **Под каждым демо стоят токены моноширинным** (`--dur-base --ease-out --shift-anchor`). Дизайн связан с кодом напрямую, разработчик копирует имена.
5. **Реальный контент продукта во всех образцах**: отели, факты, этажи, даты. Нигде нет lorem ipsum и «Button». Типошкала тоже набрана настоящими строками интерфейса.
6. **Двухуровневые токены** (примитивы → семантика), тёмная тема переназначает семантику, альфа-заливки в тёмной. Для доменной области есть отдельные наборы (`--map-*`, `--hue-*`, `--confidence-*`).
7. **Плоскость и hairline через inset shadow**, тень только у плавающего. Тёплые нейтральные вместо чисто серых.
8. **Дробные веса variable-шрифта** (450/560/650/750) и отрицательный трекинг крупных кеглей. Line-height падает с ростом кегля (1.55 → 0.98).
9. **Motion как система**: именованные кривые с назначением, пары «вход / выход» (выход короче), задержки появления скелетона и спиннера против мелькания, reduce на уровне токенов.
10. **Один фирменный жест** (раскрытие знака) переиспользован как загрузчик, приветствие, 404 и анимация в шапке.
11. **Do/Don't везде**, где есть правило (логотип, голос, чат, пунктуация, итоговые правила), с иконками ✓/✕ в status-цветах.
12. **Аннотированные анатомии**: нумерованные выноски и таблица «часть, как, токены, при reduce».
13. **Экраны как «договор о компоновке»**, а не пиксельные макеты: каркасы с названиями зон.
14. **Полнота жизненного цикла**: favicon, вкладки, OG-превью в обеих темах, 404, первый вход, пустые состояния и ошибки.
15. **Технические мелочи**: тема без вспышки (inline-скрипт в head), view transitions, `content-visibility`, skip-link, хоткеи, scroll-padding под sticky-шапку, hover только для fine pointer, свой скроллбар, `::selection` в фирменном цвете.
16. **Версия, дата и путь к источнику правды** (`tokens.css`, `build.mjs`) видны всегда. Это выглядит как живой артефакт, а не как PDF.
