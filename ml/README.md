# ML: Gemini Decision через OpenRouter

Модель `google/gemini-decision-1` отвечает на структурированные вопросы о фото: есть ли объект, какой он, какой дефект (выбор из классов), насколько опасно (шкала). На каждый ответ даёт вероятность. Цена около $0.00016 за фото, ответ около 1.5 с.

| Файл | Что делает |
|---|---|
| `taxonomy.json` | классы, их русские названия и алиасы меток, вопросы, пороги. **Утром правится только он** |
| `decision.py` | клиент API (повторы, кэш по sha256 фото) и правило маршрута |
| `worker.py` | прогон папки → `runs/<id>/predictions.jsonl` и Kafka `detections.created` |
| `evaluate.py` | отчёт против разметки → `runs/<id>/report.{json,md}`, страница «Качество» в UI |
| `labels.py` | чтение CSV/XLSX; `python labels.py table.xlsx` показывает колонки и значения |
| `smoke_decision.py` | один запрос: проверить ключ и сеть |

Ключ: `OPENROUTER_API_KEY` в `../.env`.

## Маршрут кадра

| Маршрут | Когда | Что в системе |
|---|---|---|
| `critical` | дефект и P(последний уровень опасности) ≥ `critical_prob` | тревога в обход очереди |
| `review` | дефект или неуверенная норма | очередь диспетчера |
| `auto_ok` | норма с уверенностью ≥ `auto_ok` | подтверждено без человека |
| `not_observed` | «объекта нет» или неуверенная норма при плохой видимости | в Kafka не пишется |

Видимый дефект никогда не гасится порогом видимости: у открытого люка нет крышки, и вопрос «виден ли люк» даёт низкий балл.

## Утром, по шагам

```bash
cd ml && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # один раз
.venv/bin/python smoke_decision.py <любое фото>          # 1. ключ и сеть на площадке
.venv/bin/python labels.py <таблица.xlsx>                # 2. какие колонки и значения в разметке
# 3. вписать их виды повреждений в taxonomy.json: classes / aliases (label = как в таблице)
.venv/bin/python worker.py <папка с фото> --labels <таблица> --file-col <колонка файла> \
    --kafka '' --limit 30 --run-id dry                   # 4. сухой прогон на 30 фото
.venv/bin/python evaluate.py runs/dry --labels <таблица> --file-col ... --label-col ...
# 5. весь датасет в систему (API запущен с MEDIA_ROOT=<папка с фото>)
.venv/bin/python worker.py <папка> --labels <таблица> --file-col ... [--id-col ... --lat-col ... --lon-col ...] --run-id final
.venv/bin/python evaluate.py runs/final --labels <таблица> --file-col ... --label-col ... [--status-col ...] [--map "метка=класс"]
```

- Ответы кэшируются в `.cache/<hash вопросов>/`. Повторный прогон и смена порогов ничего не стоят. Смена текста вопросов или классов означает новый кэш.
- Id детекций детерминированные, поэтому повторная публикация не создаёт дублей в бэкенде.
- Отчёт содержит перебор порога `auto_ok`: сколько снимаем с людей и сколько дефектов теряем. Это главный слайд.
