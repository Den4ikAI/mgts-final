# Авторизация и роли

Код: `backend/crates/api/src/auth/`, миграция `backend/migrations/0002_auth.sql`, фронт `web/src/app/core/auth.ts`.

## Роли и права

Права проверяются в одном месте: `Role::can` в `auth/mod.rs`. Хендлер делает `user.require(Perm::…)?`.

| Право | admin | dispatcher | manager | technician |
|---|:-:|:-:|:-:|:-:|
| `objects_read` (объекты, история, очередь, SSE) | ✓ | ✓ | ✓ | ✓ |
| `review` (подтвердить / отклонить / переснять) | ✓ | ✓ | | |
| `stats_read` (сводка) | ✓ | ✓ | ✓ | |
| `work_orders_manage` (создавать наряды) | ✓ | ✓ | | |
| `work_orders_own` (свои наряды, закрытие) | ✓ | | | ✓ |
| `users_manage` | ✓ | | | |
| `dev_tools` (`/api/dev/*`) | ✓ | | | |

Права нарядов заведены заранее, эндпоинтов нарядов ещё нет.

## Токены

| | Access | Refresh | Stream ticket |
|---|---|---|---|
| Что | JWT HS256 | 32 случайных байта, base64url | JWT HS256, `typ=stream` |
| Срок | `ACCESS_TTL_SECS`, по умолчанию 900 (15 мин) | `REFRESH_TTL_SECS`, по умолчанию 30 дней, скользящий | 60 с |
| Где у клиента | память вкладки | HttpOnly cookie `mgts_refresh`, `Path=/api/auth`, `SameSite=Strict` | query `?ticket=` |
| Где на сервере | нигде (stateless) | `refresh_tokens`, только SHA-256 | нигде |

JWT claims: `sub`, `login`, `name`, `role`, `typ`, `iat`, `exp`, `jti`. Access-токен как билет и билет как access-токен не принимаются.

**Ротация.** Каждый `/refresh` гасит предъявленный токен и выдаёт новый в той же «семье» (сессии). Если погашенный токен предъявили позже чем через 30 с, это считается кражей: гасится вся семья. В пределах 30 с это параллельный refresh из соседней вкладки: ответ 401 `…retry`, фронт повторяет запрос с новой cookie.

**Отзыв.** Смена роли, пароля или отключение пользователя гасит все его refresh-токены. Уже выданный access живёт до истечения, максимум `ACCESS_TTL_SECS`.

**SSE.** `EventSource` не умеет заголовки, а класть долгоживущий токен в URL нельзя (попадёт в логи). Поэтому фронт берёт билет `POST /api/auth/stream-ticket` и переподключается с новым билетом при каждом обрыве.

**Пароли.** Argon2id (m=19 МБ, t=2), минимум 8 символов, хеш считается вне async-потоков. Для несуществующего логина всё равно проверяется фиктивный хеш, чтобы по времени ответа нельзя было перебрать логины.

## Переменные окружения

| Переменная | По умолчанию | |
|---|---|---|
| `JWT_SECRET` | случайный на каждый запуск | ≥ 32 байт. Без него сессии умирают при рестарте |
| `ACCESS_TTL_SECS` | 900 | |
| `REFRESH_TTL_SECS` | 2592000 | |
| `COOKIE_SECURE` | 0 | `1` за HTTPS |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | `admin` / — | создать админа, если пользователей нет |
| `SEED_DEMO_USERS` | 0 (в compose 1) | `admin`, `dispatcher`, `manager`, `tech` с паролем `DEMO_PASSWORD` (`mgts-demo`) |

## Фронт

- `AuthService`: пользователь и токен в сигналах, восстановление сессии при загрузке (`provideAppInitializer`), обновление за минуту до истечения, single-flight refresh.
- `authInterceptor`: ставит Bearer; на 401 один раз делает refresh и повторяет запрос, иначе уводит на `/login?next=…`.
- `requirePerm('…')`: guard маршрута. Меню показывает только доступные разделы.
- `/users`: админка пользователей.

## Не сделано

- Лимит попыток входа (rate limit / блокировка после N неудач).
- Смена своего пароля самим пользователем (сейчас только админ через `PATCH /api/users/{id}`).
- CORS сейчас permissive и без credentials. Cookie работает, пока фронт и API на одном origin (dev-прокси или общий nginx).
